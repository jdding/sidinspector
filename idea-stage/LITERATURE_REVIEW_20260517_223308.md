## Executive Summary

The public literature supports a real but narrow gap. OPE for recommender systems already has mature estimator families, public logged-bandit tooling, and ranking/slate-specific variants. Lifecycle-aware recommendation also exists as a modeling direction. The open space is the intersection: using lifecycle state as a structured source of OPE support/positivity failure, and turning that into credibility diagnostics, policy-selection gates, or logging-budget design.

The strongest public-facing claim is therefore not "new OPE estimator for recommendation" and not "new lifecycle recommender." It is:

> Existing aggregate OPE protocols can hide lifecycle-state reliability failures; a lifecycle-stratified protocol can expose when public logged data supports credible OPE and when it only supports observational diagnostics.

## Source Groups

### 1. OPE Foundations and Tooling

**Open Bandit Dataset / Open Bandit Pipeline (OBP).**
OBD/OBP is the safest public anchor. The NeurIPS Datasets and Benchmarks paper frames OPE as estimating hypothetical policy performance from data generated by another policy, and presents OBD as public logged bandit data from ZOZOTOWN with multiple behavior policies. OBP standardizes batch bandit and OPE implementation. The documentation states that OBP includes true behavior-policy propensities and implements many estimators, including DM, IPW, SNIPW, DR, switch estimators, DRos, MRDR, and DML.

**Implication for this project**: OBP should be used first for estimator correctness and reproducibility, but it is not a strong lifecycle dataset. It is a methodological sanity baseline, not the main lifecycle evidence.

Primary sources:

- Open Bandit Dataset and Pipeline, NeurIPS Datasets and Benchmarks 2021: https://datasets-benchmarks-proceedings.neurips.cc/paper/2021/hash/33e75ff09dd601bbe69f351039152189-Abstract-round2.html
- OBP documentation: https://zr-obp.readthedocs.io/en/latest/

### 2. Slate, Ranking, and Counterfactual LTR

**Slate OPE.**
Swaminathan et al. study off-policy evaluation for policies that recommend ordered sets/slates. This is directly relevant because recommender production outputs are usually ranked lists rather than single actions. Their contribution is an estimator for logged slate data and conditions under which unbiasedness holds.

**Cascade DR for ranking policies.**
Kiyohara et al. propose Cascade Doubly Robust OPE for ranking policies under a cascade behavior model. Their motivation is that naive contextual-bandit OPE faces high variance in large ranking action spaces; reasonable behavioral assumptions are needed to control bias-variance tradeoffs.

**Counterfactual learning-to-rank.**
The Joachims/Swaminathan/Schnabel line provides the general counterfactual/propensity-scoring foundation for biased feedback in ranking. It is important prior art for position-bias and logged-feedback correction.

**Implication for this project**: any ranking/slate claim must be careful. Without logged slate propensities or defensible ranking-exposure assumptions, public datasets should be labeled D0/D1 instead of strict OPE. A lifecycle-stratified ranking-OPE idea is high-risk unless the schema supports it.

Primary sources:

- Slate OPE, NeurIPS 2017: https://papers.nips.cc/paper/6954-off-policy-evaluation-for-slate-recommendation
- Cascade DR for ranking policies, WSDM 2022: https://arxiv.org/abs/2202.01562
- Unbiased Learning-to-Rank with Biased Feedback, IJCAI 2018: https://www.ijcai.org/proceedings/2018/738

### 3. Support, Positivity, and Large Action Spaces

**OPE in embedded spaces.**
Lee, Arbour, and Theocharous explicitly identify two practical problems in recommendation/search OPE: large action spaces can create finite-sample positivity violations, and logging/target policy densities may not be available in non-probabilistic systems. Their proposed direction reduces positivity issues by computing density ratios in action embedding space.

**Deficient-support OPE.**
The broader OPE literature treats support/positivity failure as a first-class issue. This is a key novelty constraint: the project cannot claim that support failure itself is new. The possible delta is that lifecycle transitions produce structured, state-dependent support failures that aggregate diagnostics can hide.

**Implication for this project**: the novelty must be state-structured diagnosis and decision rules, not merely "positivity matters."

Primary source:

- Off-Policy Evaluation in Embedded Spaces: https://arxiv.org/abs/2203.02807

### 4. Public Recommendation Datasets

**KuaiRand.**
KuaiRand is the strongest public dataset candidate for the main idea. It is an unbiased sequential recommendation dataset with randomly exposed videos inserted into normal feeds. The paper and repository emphasize user IDs, timestamps, rich user/item features, scenario/policy information, and multiple feedback signals.

**KuaiRec.**
KuaiRec is valuable because it is close to fully observed: the public GitHub reports a small matrix with 1,411 users, 3,327 items, 4,676,570 interactions, and 99.6% density. This makes it useful for oracle-style stress tests and controlled missingness experiments, but it is not the same as logged-policy OPE with propensities.

**MIND.**
MIND has scale and impression logs. Microsoft describes it as containing 1 million users and over 160k news articles with rich textual content. It is useful for temporal/impression-scale analysis, but public MIND lacks known propensities, so strict IPS/DR claims are not appropriate.

**Implication for this project**: main public-data order should be OBP for estimator sanity, KuaiRand for lifecycle-like randomized exposure, KuaiRec for oracle stress tests, and MIND only for weaker D0/D1 temporal diagnostics.

Primary sources:

- KuaiRand arXiv: https://arxiv.org/abs/2208.08696
- KuaiRand GitHub: https://github.com/chongminggao/KuaiRand
- KuaiRec GitHub: https://github.com/chongminggao/KuaiRec
- KuaiRec arXiv: https://arxiv.org/abs/2202.10842
- MIND Microsoft Research: https://www.microsoft.com/en-us/research/publication/mind-a-large-scale-dataset-for-news-recommendation/

### 5. Lifecycle-Aware Recommendation

**STAN.**
STAN is important closest prior work. It introduces user lifecycle stages for multi-task recommendation and reports both public/industrial experiments and online A/B gains. This means "lifecycle stages matter for recommendation" is not novel.

**Other lifecycle/time-shift work.**
Older and recent recommendation literature studies user/item lifecycles, cold start, concept drift, temporal distribution shift, time interval modeling, and evolving preferences. These works support the motivation but also constrain novelty.

**Implication for this project**: lifecycle must be positioned as an OPE reliability variable, not a modeling feature. Any method idea must explain why generic subgroup robustness or lifecycle-aware modeling does not already cover it.

Primary source:

- STAN, RecSys 2023: https://pure.psu.edu/en/publications/stan-stage-adaptive-network-for-multi-task-recommendation-by-lear/

## Structural Gap

The gap that survives the literature pass:

1. Public OPE benchmarks evaluate estimator reliability, but not primarily through lifecycle-state reliability.
2. Lifecycle recommendation models optimize prediction or multi-task objectives, but do not ask when OPE evidence is credible for each lifecycle state.
3. Support/positivity failure is known, but the literature does not appear to package lifecycle transitions as a structured, deployable support-failure audit for sequential recommendation.

## Consequences for Idea Generation

Recommended idea family:

- lifecycle-state OPE credibility protocol;
- aggregate-to-state OPE reversal benchmark;
- state-conditioned support stress curves;
- public log readiness validator;
- targeted exploration-budget simulation for later production validation.

Ideas that should be treated cautiously:

- new estimator claims, unless state-adaptive thresholds show clear gains over existing switch/DRos/MRDR-style baselines;
- ranking/slate OPE claims, unless public schema supports slate propensities or a defensible cascade assumption;
- lifecycle-conditioned recommender models, because STAN and related work already cover lifecycle as a modeling signal.

## Open Novelty Questions

1. Has subgroup/group-robust OPE already covered the same idea under non-lifecycle group labels?
2. Has conservative/safe policy improvement already used worst-group lower confidence bounds in a way that makes lifecycle-conservative selection incremental?
3. Has active data collection for OPE already solved targeted exploration budget allocation under support deficiency?
4. Can KuaiRand lifecycle-like states be defined using only pre-exposure information?
5. Can the public phase produce a paper-worthy protocol without production A/B validation?
