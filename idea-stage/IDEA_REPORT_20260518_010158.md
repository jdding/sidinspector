## Recommended Ideas

### Idea 1: Evidence Validity Modeling for Lifecycle Transitions

**Question**: when a user enters a lifecycle-transition state, which preference evidence should the recommender still trust?

**Core hypothesis**: old behavior, semantic/attribute bridges, current-session evidence, catalog trend, and protected existing-source hits have different validity profiles during lifecycle transitions. A model that estimates evidence validity before ranking can improve deployable net gain and reduce cannibalization compared with generic source fusion.

**Mechanism sketch**:

1. Build candidate evidence sources: old sequential ID source, semantic/attribute source, current-session or recent-context source, catalog-trend source, protected baseline source.
2. For each user-state/source pair, estimate a validity vector: expected support, uncertainty, cannibalization risk, and conflict with protected hits.
3. Use validity to route actions: retain, suppress, promote, or probe.
4. Train with full-list outcomes and source-protection constraints, not candidate-only hit rate.

**Minimum public pilot**:

- Reuse CASP-style full-list accounting on REES46/Tmall/Synerise where available.
- Add source-validity features and compare against CASP, exact fusion, contextual MMR, learned gates, and simple source weighting.
- Primary metric: net@K with protected-hit preservation and cannibalization ratio.

**Why it may be publishable**:

It reframes the hard problem from "more support" to "which evidence is valid enough to deploy." This directly matches the wiki's strongest supported claim: support expansion is not deployment.

**Main risk**:

It can collapse into CASP/CALB if validity is just another hand-tuned gate. To survive, it needs a clear validity target, source-conflict modeling, and evidence that it generalizes beyond one CASP policy.

### Idea 2: Transition-Aware Deployable Source Arbitration

**Question**: how should a system arbitrate between existing-source hits and auxiliary-source promotions during lifecycle transitions?

**Core hypothesis**: lifecycle-transition recommendation is a constrained arbitration problem, not a retrieval problem. The system should choose interventions over source regions of the list while preserving high-confidence existing-source hits.

**Mechanism sketch**:

1. Treat each ranked list as source-labeled regions: protected existing source, semantic bridge, catalog trend, recent-session source, exploratory source.
2. Learn a transition-aware arbitration policy that chooses list interventions subject to source-protection constraints.
3. Optimize net utility: recovered hits minus cannibalized protected hits, with constraints on Top-K preservation.
4. Add uncertainty or confidence bounds over cannibalization prediction.

**Minimum public pilot**:

- Start from CASP artifacts and pressure-test learned arbitration against transparent CASP gates.
- Show that unconstrained learned gates and MMR fail because they ignore source protection, then test whether uncertainty-aware arbitration improves net gain or robustness.

**Why it may be publishable**:

It distills CASP's strongest insight into a general decision layer. The paper would be about deployable source arbitration under lifecycle transition, not about a new encoder.

**Main risk**:

The line is close to CASP. It needs a mechanism beyond the current constrained gate, such as calibrated cannibalization-risk prediction, uncertainty-aware intervention, or a theorem/guarantee around protected utility.

### Idea 3: Return-Session Preference Probing Under Protection Constraints

**Question**: when a dormant user returns, how should the system allocate the first few impressions between familiar exploitation, safe promotion, and probing?

**Core hypothesis**: the first return session is an information-acquisition window. A good system should probe uncertain evidence only when the expected value of information exceeds abandonment or cannibalization risk.

**Mechanism sketch**:

1. Define action classes rather than items: protect, promote, probe, diversify, suppress.
2. Maintain a belief over evidence validity after each early return interaction.
3. Choose the next slate intervention under a risk budget.
4. Later production validation can use logging policy and A/B outcomes; public phase can only simulate with strict caveats.

**Minimum public pilot**:

- Simulate return-session prefixes on KuaiRec/KuaiRand/H&M-like data.
- Evaluate whether probing policies recover current preference faster than fixed CASP-like promotion while preserving early precision.

**Why it may be publishable**:

This is the most production-aligned idea and least tied to the old dormant-return papers. It moves from static ranking to lifecycle-transition decision making.

**Main risk**:

Public data may not support credible intervention claims. This idea may need Huawei logging/A-B evidence to become strong.
