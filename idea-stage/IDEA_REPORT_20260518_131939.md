## Top Idea 细节

### Idea 1：AUDIT-SID

**Summary**：建立标准化诊断套件，衡量 semantic-ID tokenizer/codebook 在下游训练前后如何影响推荐质量、解码成本和稳定性。

**Core hypothesis**：

> semantic-ID generative recommenders 的成功或失败，可以由一组 tokenizer diagnostics 部分解释：utilization、collision harm、semantic-collaborative alignment、token predictability、head-tail capacity allocation、decoding cost、drift stability。

**Minimum viable experiment**：

1. 选择 2-3 个公开数据集：Amazon category subsets、MIND、H&M 或 Steam。
2. 实现对 item embeddings、SID assignments、user-item histories、generated rankings 的诊断指标。
3. 选择 2-3 类 tokenizer family：RQ-VAE/TIGER-style、ReSID-style，如果 code 可用再加入 DACT/CapsID。
4. 检查 diagnostics 是否能解释 Recall@K/NDCG、tail performance、invalid-generation rate、beam cost、temporal split robustness。

**Expected contribution**：

- diagnostic taxonomy and toolkit；
- public benchmark protocol；
- 哪些 tokenizer properties 真正影响效果的经验发现；
- 对 “只看 final Recall@K” 的系统性警示。

**Risk**：medium。最大风险是 diagnostics 与下游效果相关性不稳定。但如果负结果足够系统，也可能形成有价值的 evaluation paper。

## 为什么它优于其他选项

### 相比 generic SID method

SID/tokenizer generation 方向已经很拥挤。近期已有 recommendation-native quantization、ranking-integrated tokenizer learning、soft routing、variable-length IDs、continual tokenization、industrial semantic cluster IDs。再做一个方法需要非常尖锐的新机制。

### 相比 pure benchmark

纯 benchmark 缺少 insight，容易被看作 useful but incremental。AUDIT-SID 必须解释 failure modes，并产出可复用 diagnostics。

### 相比内部换机回归推荐

换机回归仍是 internal-grounded method Top-1。AUDIT-SID 是另一条线：public-first methodology Top-1，后续可以反哺换机回归里的 semantic evidence token 诊断。

## 推荐定位

强定位：

> A diagnostic methodology for semantic-ID generative recommenders, showing that tokenizer/codebook quality must be audited along accuracy, predictability, collision harm, drift stability, and decoding cost.

弱定位：

> We compare recent semantic-ID methods on public datasets.

## 必须包含的诊断轴

1. **Utilization**：codebook entropy、dead-code rate、prefix occupancy、branch imbalance。
2. **Collision harm**：same/prefix-near codes 是否合并了行为上应区分的 item。
3. **Semantic-collaborative alignment**：content/metadata neighborhood 与 interaction neighborhood 的一致性。
4. **Predictability**：correct SID sequence probability/rank、prefix next-token likelihood、invalid-token rate。
5. **Head-tail allocation**：tail item 是否获得足够可区分的 code capacity。
6. **Drift stability**：temporal catalog/user-behavior update 下的 SID churn。
7. **Deployment cost proxy**：token length、branching factor、beam size、invalid generation、candidate duplication。

## Public-First 边界

公开数据可以支撑：

- diagnostic taxonomy；
- public reproducibility protocol；
- static / temporal stress test；
- proxy reliability 的正负发现。

公开数据不能支撑：

- 强 production deployment claim；
- online GMV / retention 结论；
- 华为换机回归用户结论。

进入 strict novelty check 和 method refinement。实验启动前必须先过 code/data feasibility gate。
