# Findings

Append-only cross-stage discovery log for the lifecycle OPE preflight project.

## 2026-05-17

- The initial public-stage framing is `Lifecycle-stratified OPE reliability protocol under sparse support`.
- The first execution gate is public dataset feasibility, not model training.
- Current preferred public dataset order is Open Bandit Dataset / OBP, KuaiRand, KuaiRec, then MIND only as a weaker impression-scale auxiliary.
- Strict OPE claims require logged propensities, randomized exposure, or a clearly bounded estimated-propensity design.
- After expanding to 10 public-data ideas, the recommended novelty-check shortlist is: lifecycle-state OPE credibility protocol, lifecycle-conservative policy selection, and lifecycle-targeted exploration budget simulator.
- Strict novelty check verdict: proceed with lifecycle-state credibility only as a protocol/resource contribution (5/10); treat lifecycle-conservative policy selection as a cautious baseline due to group-constrained LCB overlap (3/10); treat lifecycle-targeted exploration as a cautious simulator/logging-design module (4/10). The main killer prior is DataCOPE plus high-confidence/pessimistic OPE selection; avoid claiming a new estimator.
- After novelty check, `refine-logs/EXPERIMENT_PLAN.md` was downgraded from a full execution plan to a gated schema-feasibility/protocol-preflight plan. The next gate is dataset-field audit and D0/D1/D2 readiness labeling, not model training.
- User rejected a pure resource/protocol target as below personal ambition. Early pre-novelty snapshots and provisional plans were deleted to avoid polluting later work; the live direction is now method-first refinement.
- Research-wiki reassessment changed the main conclusion again: do not continue OPE as the next mainline. Existing dormant-return evidence says gap-duration methods, simple routing, representation adapters, and public OPE are weak next-paper engines. The strongest problem candidate is preference evidence validity / lifecycle transition decision under stale, sparse, and conflicting evidence.
- Fresh idea-discovery on `codex/lifecycle-transition-reassessment` ranks Evidence Validity Modeling for Lifecycle Transitions first. First-pass novelty is 6/10: proceed only if the method defines an explicit validity target and does not collapse into CASP/CALB source gating.
- User decided 6/10 is not worth experiments. Both exploratory branches are closed as no-experiment. Future work is recorded as three separate workstreams: TOIS 5+1 synthesis, internal device-switch return recommendation, and LLM-assisted RecOps.
- REA review narrows LLM-assisted RecOps: first viable version should be a Ranking Experiment Agent for offline/nearline ranking experiment planning, execution, failure handling, and result analysis, not an end-to-end RecOps copilot.
- TOIS is now explicitly excluded from "Top-1 new direction" ranking because it waits for AC/review outcomes. After incorporating the 2026-05-18 semantic-ID/tokenizer/codebook trend, the recommended Top-1 new method direction is device-switch return recommendation with adaptive semantic evidence tokenization; generic SID/tokenizer work is treated as too crowded unless grounded in this switch-back scenario.

## 2026-05-18

- New AUDIT-SID idea-discovery branch created for public-first evaluation/diagnosis of semantic-ID tokenizers/codebooks. Pipeline verdict: proceed with caution, novelty about 7/10, but only as a diagnostic methodology paper. Pure public SID leaderboard is abandoned as low novelty. Next gate is code/artifact feasibility: at least two public tokenizer implementations must export item-to-SID mappings and generator outputs before experiments.
- AUDIT-SID venue plan corrected by paper type: because AUDIT-SID is evaluation/resource/reproducibility work, prioritize venues with explicit Resource/Reproducibility/Evaluation/Datasets tracks. Main target is SIGIR 2027 Resource/Reproducibility-style track if available; RecSys 2027 Resource/Reproducibility and CIKM 2027 Resource are natural backups. WSDM 2027 main is suitable only if the work yields strong empirical findings beyond toolkit/resource value.
- Venue strategy changed again due to recency pressure: target CIKM 2026 Resource Track as the immediate submission because it explicitly accepts dataset/protocol/software/open-source framework/evaluation-tool resources and has the nearest matching deadline. Abstract is due 2026-05-30 AoE and paper is due 2026-06-06 AoE. Gate 0 must pass by 2026-05-24 or the submission should be abandoned.
- CIKM v0 execution scope frozen: primary dataset is ReSID processed Amazon-2023 `Musical_Instruments`, backup is Amazon 2014 Beauty/Sports; must-run methods are RQ-VAE/TIGER-style SID, ReSID, and a sanity ID baseline; must-have diagnostics are codebook utilization, collision harm, semantic-collaborative alignment, and head-tail capacity allocation. DACT/drift and deployment-cost proxy are optional only if cheap.
- User raised a valid risk that RQ-VAE + ReSID plus shallow analysis may not be representative enough to justify community contribution. Method representativeness is now a hard Gate 0A: the selected methods must cover canonical SID plus a meaningful recent tokenizer innovation, and the analysis must reveal a nontrivial diagnostic finding; otherwise abandon CIKM 2026 rather than submitting a weak resource paper.
- Current docs were only partially sufficient for the user's cluster-first proposal, so `docs/SID_METHOD_CLUSTER_AUDIT.md` was added. The CIKM must-run rule is now Cluster A canonical SID + Cluster B/C recent tokenizer innovation + sanity lower bound. Evaluation is defined by questions, not leaderboard metrics: D1 capacity utilization, D2 harmful collision, D3 semantic-collaborative mismatch, and D4 head-tail capacity.
