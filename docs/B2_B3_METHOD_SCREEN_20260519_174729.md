No new third named tokenizer should enter the main evidence table from this
screen.

only with local compatibility repair files because the official tree lacks the
required quantizer modules. It is therefore failed for v0 main evidence, not
merely pending real input/checkpoint/export.

## Candidate Notes

### QuaSID

Primary page checked: <https://arxiv.org/abs/2603.00632>.

QuaSID is highly relevant to D2/D3 because the paper targets heterogeneous
collisions, qualification-aware repulsion, and collaborative signal injection.
The arXiv metadata page confirms the method and its collision/collaborative
claims, but this screen did not find an official runnable code release or a
ready item-to-SID export path. It remains a strong motivation for D2b
interaction-qualified collision harm, not an empirical row.

### AdaSID

Primary page checked: <https://arxiv.org/abs/2604.23522>.

AdaSID is a strong B2 candidate in principle because it adaptively regulates
SID overlaps and reports improved utilization/diversity. The current screen
found no official runnable repo or released SID artifacts. It should stay in
method coverage as a collision/capacity motivation until a direct export is
available.

### CapsID

Primary page checked: <https://arxiv.org/abs/2605.05096>.

CapsID is relevant to B2/B4 because it introduces soft routing and
variable-length SIDs. It is too new and no runnable artifact was found in this
screen. It is useful for explaining why D4/D5a/D7 matter, but it cannot support
CIKM v0 empirical claims.

### DIGER

Primary repo checked: <https://github.com/junchen-fu/DIGER>.

The repository README states that the current release is an illustrative /
reference implementation and that runnable code, processed data, and
pre-trained RQ-VAE checkpoints are still planned. Local source inspection
matches that boundary:

- `README.md` requires semantic embeddings and a pre-trained RQ-VAE checkpoint.
- `config/beauty_jo.yaml` still uses placeholder paths for those assets.
- `trainer.py` can save `.code.json` during training, but there is no
  independent item-to-SID export CLI that can be run against AUDIT-SID inputs.

Decision: reject DIGER for v0 main evidence. Keep it as B3/D7 motivation.

### CARD

Primary repo checked: <https://github.com/HAI-UESTC/CARD>.

CARD has two materially different paths:

1. Current repaired `rqvae4` runner: runnable and useful for source/integration
   smoke, but the project already documents it as a nearest-neighbor VQ
   compatibility repair, not faithful CARD-specific Sinkhorn/non-uniform
   quantization.
2. Original `nu-rq-vae` path: `main.py` and `generate_code.py` are designed to
   train from `item_emb.parquet` and export `codes.npy` plus
   `_item_ids.npy`, but the import path references `nu_rqvae4` while the local
   clone only has `nu-rq-vae/models/nu_rqvae.py`.

Decision: current CARD results remain smoke/control evidence. CARD can only
be reconsidered as a named evidence row after the authors provide a complete
source tree, checkpoint, processed CARD embeddings, or item-to-SID mappings.
Local compatibility repairs are not sufficient because they fill missing
quantizer semantics.

## Effect On The Experiment Plan

This screen closes the immediate third-method search for the current turn:
there is no low-risk B2/B3 method to add locally today. The best local
strong-accept lift is therefore:

1. strengthen same-dataset A/B evidence already available;
2. surface GRID Musical three-seed stability;
3. sharpen findings around collision-free capacity vs collaborative alignment;
4. keep QuaSID/AdaSID/CapsID/DIGER as coverage/motivation, not evidence.
